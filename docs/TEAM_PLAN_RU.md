# План команды для проекта Server Room

Команда из пяти человек создаёт интерактивную серверную на C++ и OpenGL 3.3+ по теме 27. Ергун отвечает за основу приложения и интеграцию, Даниал за помещение и стойки, Нурадилет за камеру и управление, Бекасыл за свет и анимацию, Даурен за текстуры и кабельные лотки. Каждый пишет код, делает собственные коммиты, готовит материал для отчёта и выступает на защите.

Репозиторий: https://github.com/gTurboflex/compgraf-final

## Источники и статус проекта

Требования преподавателя взяты из предоставленных `Final project requirements.pdf`, страницы 1-12, и `Final project topics.pdf`, описание темы 27 на странице 9 и общие правила на страницах 1, 10-11. Изображение `topic.jpg` подтверждает описание темы. Документы просмотрены 28 октября 2026 года.

В репозитории на момент проверки есть стартовое окно GLFW/GLAD, OpenGL 3.3 core, CMake и локальный GLAD. Камеры, 3D-сцены, геометрии, освещения, текстур и готовых шейдерных файлов ещё нет. Все задачи ниже являются планом реализации. Названия новых файлов и интерфейсов предлагаются для согласованной работы команды.

Дата защиты, операционная система компьютера TA и отдельный Final Project Report Template пока не указаны. Сроки ниже привязаны к защите, а разделы отчёта необходимо перенести в настоящий шаблон курса.

Пять одинаковых стоек не следует использовать как единственное подтверждение разнообразия объектов. Мигающие emissive LED визуально светятся, но сами по себе не заменяют два источника, которые реально участвуют в расчёте освещения поверхностей.

Если отсутствует любое R1-R8, оценка за Technical depth ограничивается 60% этого критерия. Если проект не собирается, по рубрике весь проект ограничивается 50%.

## Обязательная часть темы 27

1. Ряды серверных стоек: одна модель используется многократно.
2. На каждом сервере есть маленькие emissive LED-квадраты. Их мигание рассчитывается в шейдере с различающимися задержками или seed.
3. Холодное синее потолочное освещение.
4. Камера для прогулки по комнате.
5. Клавиша переключает помещение в режим перегрева с мигающим красным освещением.
6. Финальный эффект демонстрации: спокойная синяя серверная целиком переходит в красную тревогу.

Предлагаемый масштаб первой версии: комната примерно 12x18 условных метров, два ряда по четыре стойки, по шесть серверных блоков на стойку. Это рабочий масштаб команды, а не числовое требование преподавателя. Увеличивать число стоек следует после измерения FPS.

## Дополнительные функции и цели по баллам

Сначала команда завершает Core и R1-R8. После этого реализует две функции из списка Stretch темы:

| Приоритет | Функция | Кто делает | Что показать |
| --- | --- | --- | --- |
| 1 | Кабельные лотки и текстурированные плитки пола | Даурен; Даниал выделяет место в комнате | Лотки с кабелями, читаемый рисунок плитки, корректный масштаб текстуры |
| 2 | Туман холодного воздуха | Бекасыл | Зависимость тумана от расстояния, заметная на длинном проходе, без потери читаемости сцены |
| 3, при наличии времени | Монитор с живым графиком FPS | Даурен получает историю измерений от Нурадилета | График на поверхности 3D-монитора действительно меняется по данным времени кадров |

«Кабельные лотки и текстурированный пол» считаем одной связанной stretch goal, чтобы не рассчитывать на двойной балл за один пункт темы. Две работающие stretch goals дают до 8 баллов A5, по 4 за каждую. График FPS не обязателен для базового счётчика R7.

Для высоких баллов дополнительно нужны 60+ FPS при 1280x720, три осмысленных взаимодействия, подсказки управления на экране, единый визуальный стиль и модульный код. Минимальный порог производительности остаётся 30+ FPS.

## Соглашения перед началом параллельной работы

Ергун публикует эти соглашения в `docs/interfaces.md`, остальные подтверждают их до написания зависимого кода.

1. Координаты: Y вверх; единицы сцены одинаковы у всех. Начальная камера стоит в проходе. Угол обзора, near/far и ориентация согласуются с Нурадилетом.
2. Вершина Mesh содержит position, normal, UV. Статические буферы создаются один раз. Mesh не загружает текстуры и не компилирует шейдеры каждый кадр.
3. `SceneNode` хранит локальную матрицу, родителя и дочерние узлы. Мировая матрица ребёнка получается как `parentWorld * localTransform`. Для двери локальные преобразования учитывают положение петли.
4. Camera отдаёт view, position и projection либо необходимые параметры projection. Обновление передвижения использует `deltaTime`.
5. `FrameContext` передаёт время, `deltaTime`, view, projection и позицию камеры. Параметры материала, текстуры и источников передаются согласованным способом.
6. InputController создаёт действия `ToggleAlarm`, `ToggleNearestDoor`, `ToggleCeilingLights`, `ToggleHelp`, `ToggleMouseCapture`. App направляет действия соответствующему модулю. Переключение срабатывает один раз на нажатие.
7. ServerRoom создаёт расположение объектов и предоставляет действие ближайшей двери. AlarmController хранит состояние тревоги; Lighting формирует свет для обоих режимов. Состояние тревоги имеет одного владельца.
8. LED получает время и стабильный seed объекта; частота и фаза различаются между серверами. В общей сцене должны работать одновременно геометрия Даниала и шейдеры Бекасыла.
9. Texture Даурена загружает ресурс один раз, создаёт mipmaps и освобождает OpenGL-объект. Пути к `assets/` и `shaders/` должны работать после чистой сборки, а не зависеть от абсолютного пути на ноутбуке.
10. UI показывает краткую помощь и FPS поверх приложения. Если нужна новая библиотека для текста, сначала проверить её совместимость с правилами курса и включить её исходники и лицензию в репозиторий.

## Даниал

**Роль:** геометрия серверной и иерархия объектов. Ветка первого задания: `feature/daniyal-scene`.

2. Создать ServerRack из повторно используемых кубов или другого простого mesh: корпус, серверные блоки, вентиляционные элементы. Сделать места для LED-квадратов на каждом сервере.
3. Расставить копии стоек в два ряда. Использовать один набор геометрии со своими model-матрицами, а не загружать одну и ту же модель заново для каждой стойки.
4. Создать стены, пол как основу для текстур Даурена, потолочные светильники, блок охлаждения, монитор со стойкой и настенную панель управления. Вместе со стойкой это пять явно разных типов объектов уже до stretch goals; кабельный лоток Даурена добавится позже.
5. Сделать дверцу дочерним узлом стойки. Реализовать плавное открытие вокруг петли и выбор ближайшей двери по расстоянию до камеры. Нурадилет вызывает это действие по `E`.

7. Сделать скриншоты общего вида, одной стойки и открытой дверцы. Подготовить схему `стойка -> дверца/сервер -> LED` и формулу мировой матрицы.

**Что загрузить:** `src/scene/ServerRoom.*`, `ServerRack.*`, `RackDoor.*`, свои оригинальные модели, если они используются, скриншоты и `docs/report/daniyal.md`. Внешние модели загрузить только вместе с разрешённой лицензией и записью в CREDITS.

**Критерий готовности:** по комнате можно пройти, видны ряды стоек и разные предметы; дверь корректно вращается у петли и остаётся частью стойки при изменении её положения.

**Отчёт:** Project Description, устройство сцены и объектов, матрицы и иерархия в Technical Implementation. Подготовить три различные статьи Q1-Q2 о моделировании сцены, преобразованиях или повторном использовании геометрии. На защите объяснить model-матрицы и parent-child преобразования.

## Бекасыл

**Роль:** освещение, GLSL, LED и режим перегрева. Ветка первого задания: `feature/bekasyl-lighting`.

1. Согласовать с Ергуном атрибуты вершин и имена uniform; с Дауреном способ передачи текстуры и свойств материала. Подготовить `scene.vert` и `scene.frag` для общей геометрии.
2. Реализовать per-fragment Blinn-Phong или Phong: ambient, diffuse, specular, положение камеры, затухание источников и корректное преобразование нормалей, включая неравномерный масштаб.
3. Подключить минимум два настоящих источника, освещающих поверхности. Для выбранного плана использовать два синих потолочных и красный источник тревоги. Проверить, что освещение заметно меняется по поверхности и даёт блик.
4. Сделать `led.vert/led.frag`: emissive-квадраты на серверах мигают в шейдере по времени, с разными стабильными seed, фазами или интервалами. Не заставлять все LED мигать синхронно.
5. Написать AlarmController. Действие `1` включает и выключает режим перегрева: вся сцена меняет спокойный синий характер на пульсирующий красный. Действие `L` независимо переключает потолочные источники. Согласовать их совместное поведение.
6. После готовности всей обязательной сцены добавить туман холодного воздуха как вторую stretch goal: коэффициент зависит от расстояния до камеры, итоговый цвет смешивается с цветом тумана. Проверить результат в обоих режимах и измерить влияние на FPS вместе с Нурадилетом.
7. Подготовить сравнение синего и красного режимов, LED и тумана; выписать уравнение освещения и тумана для отчёта и объяснения на защите.

**Что загрузить:** `src/effects/Lighting.*`, `AlarmController.*`, `shaders/scene.vert`, `scene.frag`, `led.vert`, `led.frag`, скриншоты и `docs/report/bekasyl.md`.

**Критерий готовности:** видны объём, diffuse и specular, работают реальные источники света, LED мигают с различными фазами, тревога меняет всю комнату; туман добавляется после Core и не скрывает ошибки освещения.

**Отчёт:** Lighting and Shading, шейдеры LED, тревога и fog в Graphics and Rendering; ключевые уравнения и ограничения. Подготовить три различные статьи Q1-Q2 об освещении, shading или atmospheric effects. На защите объяснить один shader/algorithm на формуле или фрагменте собственного кода.


Ергун использует существующую папку `/Users/ergun/grafika/compgraf-final`; повторное клонирование поверх неё не требуется.

### Ветка под своё задание

После публикации основы Ергуном каждый обновляет `main` и создаёт свою ветку. Пример Даниала:


Для остальных первые ветки: `feature/ergun-core`, `feature/nuradilet-camera`, `feature/bekasyl-lighting`, `feature/dauren-textures`. Под новое самостоятельное задание после слияния предыдущего создаётся новая ветка.

### Коммит и загрузка

1. Сделать небольшой работающий этап и собрать приложение.
2. Выполнить `git status` и проверить, какие файлы попадут в коммит.
3. Добавить только файлы своего этапа, создать понятный коммит и отправить ветку. Пример Даниала после создания указанных файлов:

```bash

git commit -m "Add reusable server rack geometry"
git push -u origin feature/daniyal-scene
```

Коммитить завершённые шаги регулярно в течение проекта. Не собирать всю работу пятерых в один последний коммит от Ергуна и не передавать код только архивами в мессенджере.

### Pull Request и объединение

1. На GitHub открыть Pull Request своей ветки в `main`.
2. Описать, что готово, как проверить, какие файлы изменены, и приложить скриншот. Указать зависимости от чужих задач.
3. Ергун или назначенный участник собирает ветку и проверяет функцию. Слияние делает только после проверки.
4. При слиянии сохранять авторство и историю участников; для этого удобно Create a merge commit. Не заменять вклад всех одной переписанной копией.
5. После слияния и при чистой рабочей папке обновить `main`. Существующую рабочую ветку при необходимости обновлять через `git fetch origin` и `git merge origin/main`, решая конфликты с владельцем общего файла.

Не добавлять `build/`, исполняемые файлы, временные файлы редакторов и `.DS_Store`. Исходники, GLSL, текстуры, лицензии, сведения о тестировании и финальные документы входят в репозиторий. Для большого демовидео удобнее unlisted YouTube и ссылка в `docs/video/link.md`; файл или ссылка также сдаются в Moodle.
